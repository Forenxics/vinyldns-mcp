# Development guide

## Layout

```
src/
  main.rs      entry point: configuration, logging (stderr), stdio transport
  lib.rs       module exports (lets integration tests run the server in-process)
  config.rs    environment configuration (validated at startup)
  signer.rs    AWS SigV4 signing, matching the VinylDNS Aws4Authenticator
  client.rs    signed reqwest client, error mapping and hints
  pending.rs   store of planned changes (single-use tokens with a TTL)
  server.rs    MCP tools, the plan/confirm workflow, server info
  server/
    admin.rs   zone management and batch review tools (separate tool router)
tests/
  common/      shared end-to-end helpers (test MCP client, configs)
  e2e.rs       MCP client ↔ server over an in-memory transport ↔ wiremock VinylDNS
  e2e_admin.rs the same for the zone and batch review tools
  fixtures/    signatures generated by the Python reference implementation
scripts/
  vinyldns_sig_reference.py   independent port of the server's signature check
  smoke_test.py               live test against a real VinylDNS
  smoke_test_admin.py         live test of the zone and batch review tools
  changelog_section.py        extracts release notes from CHANGELOG.md (+ its tests)
.github/workflows/
  ci.yml                      fmt, clippy, tests on Linux/macOS/Windows, MSRV, workflow lint
  release.yml                 builds and publishes release binaries on version tags
```

## Everyday commands

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test                    # unit + end-to-end tests (no network needed)
cargo build --release
```

CI (`.github/workflows/ci.yml`) runs the same checks.

## Request signing and how it is verified

VinylDNS checks an AWS SigV4-style `Authorization` header (see
`modules/api/src/main/scala/vinyldns/api/route/Aws4Authenticator.scala` in
vinyldns/vinyldns). Getting it wrong gives `401` on every call, so it is tested
three ways:

1. **AWS test vector.** `signer::tests::matches_aws_get_vanilla_test_vector`
   uses the `get-vanilla` case from the official SigV4 test suite.
2. **Independent reference port.** `scripts/vinyldns_sig_reference.py` is a
   line-by-line Python port of the Scala authenticator. It generates
   `tests/fixtures/*.sig`, and the Rust signer must reproduce them. To
   regenerate a fixture:
   ```sh
   scripts/vinyldns_sig_reference.py POST \
     'http://localhost:9000/zones/batchrecordchanges?allowManualReview=false' \
     '{"changes":[]}' 20150830T123600Z testUserAccessKey testUserSecretKey \
     > tests/fixtures/post_with_query.sig
   ```
3. **Live server.** `scripts/smoke_test.py` runs against a real API.

Details that matter: the server canonicalizes the **decoded** path; query
parameters are decoded, re-encoded keeping only RFC 3986 unreserved characters
(`*` becomes `%2A`, space becomes `%20`), and sorted; only `host;x-amz-date` are
signed, which avoids differences in how `content-type` is canonicalized.

## Live smoke test against the VinylDNS quickstart

```sh
# in a vinyldns/vinyldns checkout
cd quickstart && ./quickstart-vinyldns.sh --api
# in this repo
cargo build --release && scripts/smoke_test.py target/release/vinyldns-mcp
```

The script connects the `ok.` zone as the `ok` test user, then exercises the
read tools, create/update/delete through plan and confirm (waiting for each
change to reach `Complete`), a batch change, and discarding a plan.

`scripts/smoke_test_admin.py` covers the admin tools on the quickstart's
`dummy.` zone: connect, ACL rule add and remove, update (checking that the
ACL rules and connection survive by writing a record afterwards), sync and
delete. It then submits a batch change that the quickstart routes to manual
review, checks that a regular user gets 403 when approving it, and approves
it as `support-user`.

Notes on running the quickstart in containers or CI:

- Without IPv6, the integration image's nginx fails on `listen [::]:80`.
  Rebuild it without those lines:
  `FROM vinyldns/build:base-test-integration-latest` +
  `RUN sed -i '/\[::\]/d' /etc/nginx/sites-available/default /etc/nginx/sites-enabled/nginx_proxy.conf`.
- `vinyldns/api:latest` currently fails against that image (`Unsupported
  Database: MariaDB 10.3`). Use `vinyldns/api:0.20.2`:
  `VINYLDNS_IMAGE_VERSION=0.20.2 docker compose --env-file .env up -d --no-build api`
  (after tagging the integration image as `base-test-integration-0.20.2`).
- The script needs the `docker-compose` command. With Compose v2 only, a shim
  that runs `exec docker compose "$@"` works.

## Adding a tool

1. Add a parameter struct (`Deserialize + JsonSchema`, with doc comments; they
   become the schema descriptions the model reads).
2. Add an `async fn` in the `#[tool_router] impl VinylDnsServer` block with
   `#[tool(description = …, annotations(…))]`. Set `read_only_hint` and
   `destructive_hint` accurately.
3. For writes, add a `PlannedAction` variant, a `plan_*` tool that calls
   `store_plan`, an arm in `VinylDnsServer::apply`, and the tool name in
   `WRITE_TOOLS`. Admin tools go in `src/server/admin.rs`: their apply arm is in
   `apply_admin`, and their names are listed in `ADMIN_TOOLS`.
4. Add an end-to-end test in `tests/e2e.rs` or `tests/e2e_admin.rs`, and update `docs/TOOLS.md`,
   `CHANGELOG.md` and `docs/TASKS.md`.

## Versioning and releases

- [Semantic Versioning](https://semver.org). Before 1.0, a minor version bump
  can change tool names or parameters.
- [Keep a Changelog](https://keepachangelog.com) format in `CHANGELOG.md`.
  Add entries under **Unreleased** with each change.
- The release process, the published binaries, and how to check the release
  pipeline locally are described in [RELEASING.md](RELEASING.md).
